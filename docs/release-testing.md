# ucdk release: testing plan

Status: design (Proposal). This page is the full text of section 8 of [release.md](release.md); it is split out only to keep that file under the project's size bound. Section numbers below without a file name are those of release.md.

## 8. Testing plan (Proposal)

Rules that bind every layer: tests are Rust (SDK tests in their own language, scoped to the binding); every crate on its own reaches 99% of lines and branches (`cargo xtask coverage`, Exists), from its first PR, so each PR in 11 names the pure functions it lands and its test list is the minimum; a bug fix ships with a test that failed first; each test is documented by name and the behaviour it asserts; workflow `run:` lines are single `cargo xtask` verbs; **no test asserts timing**. Polls and backoff are counted through `Pause`; leases move through `ManualClock`, which the ledger under test and the fakes share (3.1); `LeaseGuard` reads time only through the ledger (3.1), the engine and every seam take `Pause` and `Heartbeat`, and `SystemTime::now` is read only in `SystemClock` (3.3). **Every pull-request suite uses in-process emulators and temporary directories and needs no network and no credentials; a live registry is never reached from CI.** The directory publisher's kit runs against a temporary directory, the `Buck2` and `Bazel` kits against a scripted process runner, and the package-registry publisher and its grant source against an in-process loopback emulator of the registry's staging, commit and grant-exchange routes.

**By layer.**

| Layer | What is tested | How | Defect class it catches |
|---|---|---|---|
| `ucdk-core` | path and key grammar, hash hex rules, framing, Kahn order | unit; golden for key and framed hash text; order on cycles and unknown needs | a changed key or hash that orphans stored records; nondeterministic order |
| `ucdk-release-proto` | wire bytes, descriptor shape | golden bytes per message; descriptor breaking-change check; reserved numbers listed | a renumbered or retyped field |
| `ucdk-release` | machine validation (the worked example of 1.2 is read whole), selection, the set, machine, run, build-inputs and action-input hashes, the invocation layering, the listing and report parsers, `decide_publish`, `account_rows`, state codec | one unit test per refusal naming its rule; goldens for each hash text and each argument vector; exhaustive tables of (presence, digest, yank, monotonic, history) to verdict; transition table total over every (state, event) | a rule silently not enforced; a set hash that includes the run or attempt that built it, or leaves out the producing stage; a hash that moves when an input it should ignore moves, or ignores one it should cover; a vacuous pass |
| seams and kits | the contract every implementation meets | kits on the fakes; kit self-test with non-conforming stubs | a kit scenario that cannot fail |
| `ucdk-release-fake` | fakes obey their own kits; each fault switch does what it says | kit plus per-fault tests and call-log tests | a fake that hides the defect it should expose |
| `ucdk-ledger` | CAS, lease, fence, format, guard | conformance on both ledgers; file torn, corruption, newer-major tests; guard tests on `ManualClock` | a lost update; a torn file read as a ledger; a stalled holder writing |
| `Buck2` and `Bazel` (PR 12a) | the argument vector and environment of each verb, the bare-binary lookup on the child's `PATH`, the parse of the output listing and of the test report | the kit over a `FakeProcessRunner` scripted with transcripts of real runs; argv goldens | a flag spelling or a layering order that drifts; a listing read wrongly; a test that ran nothing counted as a pass |
| `ucdk-release-engine` | build, test and publish actions (5.2), resume (5.4), grants, yank, admission | integration over the fakes with call logs; crash sweep | a stage or commit before its intent; a delete; a different digest overwritten; a commit made with a stage grant; a stage admitted that was not confirmed |
| `ucdk-api`, `ucdk-capi`, `ucdk-cli` | conversions, exit table, ABI, text | round trips; exhaustive match; in-process ABI conformance; CLI goldens over a world of fakes | an unmapped verdict; ownership, panic and version defects |
| SDKs and generator | binding and generated code | wire goldens, shared scenario files, end to end through the real library, `sdk-fresh` | an SDK that disagrees with the core or the other SDK; stale generated code |

**By the spine of 2** (each holder of validations, in the order a stage runs them):

| Holder | What is tested, and where | Defect class it catches |
|---|---|---|
| Build action | one invocation per artifact in `needs` order with the layered command (`build::one_invocation_per_artifact_with_the_layered_command`); the one output located and copied, the manifest composed from the store (`build::the_manifest_is_composed_from_the_store_not_the_build_tree`); two verifications and the set document before the seal; adoption and its five refusals (5.4); a NOOP build still reaches its validations (`resume::an_adopting_run_evaluates_the_build_actions_validations`) | a member that differs from what was listed; a seal over unverified bytes; an adopted set no validation ever read |
| Build action's validations | `SET_CLOSURE` derives one row per member and records the set it read; a record for the same set is skipped as `NOOP` (`validation::a_set_closure_validation_confirmed_for_the_same_set_is_noop`) | a closed set that was never checked; a stale record taken for a new set |
| Test action | one row per target, a target that ran nothing or whose report cannot be read is not a pass; a failure leaves the record unconfirmed and is run again, never `NOOP` (`test_action::*`, `resume::a_failed_test_action_is_run_again_and_its_failure_is_not_in_the_ledger`); renewal on progress (`lease::a_test_longer_than_the_ttl_that_reports_progress_keeps_both_leases`) | a green stage that tested nothing; a failure remembered as a pass |
| Publish action | stage, then its validations, then commit, with two grants (`publish::*`); staged state is observed with the action's grant on a `PUBLIC` repository too, where a stranger's read cannot see it (`publish::staged_state_is_observed_with_a_grant_on_a_public_repository`); a grant inside the margin is exchanged again (`grant::*`); a stage grant that expires during a long validation does not matter and a staged state that vanished is refused and staged again (`publish::stage_grant_expiry_before_commit_is_invisible_the_commit_uses_its_own_grant`, `publish::staged_state_reaped_during_validation_is_refused_and_a_rerun_stages_again`); a selected Publish action keeps its pre-commit validation (`publish::a_selected_publish_action_runs_its_pre_commit_validation_before_the_commit`) | a commit made without the gate, with the wrong grant or over staged state nobody looked at |
| Smoke action and its validations | the read-back as a stranger sees it (`smoke::a_smoke_action_reads_back_as_a_stranger_on_a_public_repository`); a `CHANNEL_READBACK` is never skipped as `NOOP`; a stage-level read-back covers every Publish action of the stage, each through its own channel (`readback::a_stage_level_readback_covers_every_publish_action_and_each_channel`, `readback::a_stage_with_a_publish_and_a_smoke_action_reads_each_coordinate_under_its_holder`) | a package that was committed and is not readable |
| Stage validations and confirmation | the stage record's `confirmed` is written last and only when every action and every validation at both levels passed (`run::a_stage_is_confirmed_only_after_every_action_and_validation_at_both_levels`); a stage whose stage-level read-back fails leaves the next stage refused with zero calls (`stage_admission::a_failed_stage_level_readback_leaves_the_stage_unconfirmed_and_the_next_stage_is_refused`) | a gate that opens over a failed check |

**Crash and fault sweep.** Run a machine to completion on a fake world and count seam calls and ledger writes. Then for every N, run again stopping at call N (a kill modelled as the end of the run function with ledger and fakes kept), run once more to resume, and assert:
- the channel holds each coordinate at most once and only with the sealed digest;
- no record is `Confirmed` without a read showing it after;
- no `stage` record is `confirmed` while an action or a validation record of the stage is not `Confirmed`;
- every `stage` and every `commit` is preceded in the combined log by its intent write, and every `commit` by the exchange of a commit grant and an observation of the staged state;
- no `commit` is made with a grant that was exchanged for the stage phase, and no grant is exchanged before a local refusal;
- no record, no error and no report holds a value the fake grant source issued (a scan of every ledger byte and every message for the issued secrets);
- the final report equals the uninterrupted run's except for attempts.

It runs on the memory and the file ledger, a pass with the run ledger wiped between the stopped run and the resume (the run must then refuse a stage that needs another, never pass it, and leave no registry state changed), a pass with the run ledger as it was before the stopped job (the stage resumes, `observe` resolves every coordinate and none is published twice), and a further pass runs the same releases through `lose_answer_after_commit` at every stage and commit. Lease checks: a dead holder blocks the next run until the clock passes lapse plus skew; a holder whose clock moved past its lease is refused at its next write and changes nothing after.

**Gates are proven.** For each refusal in 5.2, 5.6 and 5.7, a test asserts that the registry's commit and stage logs are empty and the grant source saw zero exchanges, and that includes the admission refusal of a stage that is not confirmed because a validation failed or did not run. A run that has lost its run lease, or its channel lease, makes zero registry writes after the loss (`publish::run_lease_lost_means_zero_registry_writes`, `publish::channel_lease_lost_means_zero_registry_writes`). A panic during a publish ends in class 6 (`abi::release_run_panic_is_class_6`).

**End to end.** One scenario set (machine, flags, expected class, golden text) is run in process by the CLI tests and through the built library by the Python and TypeScript tests, comparing the same expected values (the mechanism exists today for deploy scenarios: `ucdk-cli/tests/scenario.rs` and the SDK tests read the same data): `build_test_publish_smoke` (the worked example of 1.2 over the fakes), `rerun_is_noop`, `resume_after_kill_between_stage_and_commit`, `resume_after_kill_during_commit`, `conflict_refused`, `validation_failed_exit_7`, `a_test_target_that_fails_is_exit_7`, `a_test_target_that_runs_nothing_is_not_green`, `indeterminate_is_never_green`, `selective_run_says_so`, `a_selected_publish_action_keeps_its_pre_commit_validation`, `superseded_runs_nothing`, `yank_then_republish_refused`, `a_refused_commit_grant_reports_the_staged_state`, `an_expired_commit_grant_is_exchanged_again_and_the_run_succeeds`, `a_stage_grant_that_expires_during_a_long_validation_still_commits`, `abort_gives_back_the_staged_state`, `a_changed_build_flag_is_not_adopted`, `resume_with_new_run_id_after_partial_publish`, `a_new_run_id_that_adopted_a_set_is_admitted_by_the_next_stage`, `stage_needing_an_unconfirmed_stage_is_refused`, `a_failed_stage_readback_refuses_the_next_stage`, `a_test_only_stage_after_a_publish_stage`, `long_build_under_a_manual_clock` (a build whose clock passes the TTL several times, with beats and then silent), `change_check_on_a_pull_request_revision`, `stage_after_an_approval_wait_in_the_same_run`, `two_platforms_share_one_store_and_one_seal_ledger` (two BUILD stages and two PUBLISH stages of two platforms under one run id).

**Where it runs.**

| Suite | Pull request | After merge or on demand |
|---|---|---|
| `check` (fmt, clippy, deny, SPDX, run lines, direction, purity, unsafe scope, public-text lint, sign-off, sdk-fresh) | yes | yes |
| unit, golden, kits on fakes, crash sweeps, 99% floors (`coverage`) | yes | yes |
| ABI conformance in process, header and symbol check | yes | yes |
| SDK conformance (`sdk-test`) | Linux | all supported platforms |
| built `cdylib` loaded dynamically, sanitizer builds, exhaustive sweeps on large machines | no | yes |
| Miri on pure paths | no | yes |
| Miri on the `ucdk-capi` ownership and panic suites (the unsafe-bearing crate), from PR 10, through the new verb `cargo xtask miri`. Miri runs only on a nightly toolchain, so PR 10 adds a second pin, `rust-toolchain-miri.toml`, read by `xtask` (rustup does not read it): a dated nightly (`nightly-<date>`, never the bare channel) with the components `miri` and `rust-src` (Miri builds its own standard-library sysroot from `rust-src` with `cargo miri setup`, which downloads the standard library's dependencies). Every `run:` line of the workflow is `cargo xtask <verb>` (the runlines gate, Exists), so there is no setup step to put an install in: `cargo xtask fetch` installs the pinned toolchain with both components through `rustup`, as `cargo xtask coverage` does for its nightly, and then runs `cargo miri setup`, so everything that needs the network happens in `fetch`; the Miri job's two lines are `cargo xtask fetch` and `cargo xtask miri`. `cargo xtask miri` itself runs offline (`--offline`, `CARGO_NET_OFFLINE`) and, when the toolchain, a component or the sysroot is missing, refuses and names `cargo xtask fetch` instead of downloading, which keeps the gate offline. `coverage.rs` says its nightly is the only place a nightly appears; PR 10 edits that comment, since the Miri pin is a second (a nightly that carries `miri` is not always the one coverage pinned, so the two may move apart). A pull request that changes the pin must pass the Miri suites. The verb set of 3.1 is unchanged until then | yes | yes |
| a real implementation's kit against its own emulator (in its own crate) | yes | yes |
| `Buck2` and `Bazel` against the real binaries on a small fixture workspace: the argument vector of each verb, the output listing, the test report and its `ran` count, that each verb accepts the author's flags (the confirmation 4.2 and 2 promise before PR 12a is accepted) | no | on demand, a named job; the build system's own downloads are the only network it may use |
| a registry over the network | never | explicit flag, named account, no CI |
